## 1. 硬件、协议和总体架构

### 用户提问

> 要做一个之前提到过的八重洲 FT-710 短波机的扩展控制设备，采用微雪ESP32-P4-WIFI6-LCD-TOUCH-7B  7英寸 触摸屏 查找并认真分析它的架构，芯片（包括外围芯片）开发文档，示例应用等信息。同时查阅YAESU FT-710 USB CAT 协议文档，给出一个可行的方案和架构

### 已交付回答

完成了 [[02_技术可行性与架构方案]]，覆盖：

- ESP32-P4 主处理器、ESP32-C6 无线协处理器及板级外围器件。
- 7 英寸 1024 × 600 MIPI-DSI 显示、GT911 电容触摸和板载接口。
- FT-710 USB CAT 的 Enhanced COM Port、串口配置和主要命令。
- USB Host 与 CP210x VCP 驱动路径。
- LVGL 图形架构、任务划分、状态模型、命令队列与异常恢复。
- 已知风险、验证顺序和可替代方案。

### 分析依据与决策摘要

- FT-710 的 USB 设备侧串口经 CP210x 暴露，控制器必须承担 USB Host 角色。
- ESP32-P4 负责显示、触摸、USB Host 和应用逻辑；ESP32-C6 负责 Wi-Fi 6 / BLE，二者职责分离。
- 初版优先使用 Enhanced COM Port，避免与标准串口用途混淆。
- CAT 层必须做命令节流、超时、重试、解析和状态回读，不能把界面按钮直接绑定为无状态串口写入。
- 频率、模式、功率、DNR 等采用统一 RadioState 作为界面显示和回读校准的唯一状态源。

## 5. 模式与波段解耦，开源项目调研

### 用户提问

> 波段选择和模式无需联动，另外，查询github 以及gitee 看看有没有任何接近的项目可以借鉴

### 已交付回答

原型中的模式与波段状态已改为互不联动。完成了 GitHub 和 Gitee 的近似项目检索，结论与链接见 [[05_GitHub与Gitee项目调研]]。

### 分析依据与决策摘要

- 界面层不因选择波段而主动切换模式，也不因模式变化而改变波段高亮。
- 真实 FT-710 的 BS 波段命令可能恢复该波段的 Band Stack 记忆，包括模式；因此“界面不联动”和“电台不改变模式”是两个不同要求。
- 若硬件阶段要求选波段时严格保持模式，应发送目标频率的 FA 命令，或在 BS 后读取并恢复模式。
- 没有发现可直接烧录并同时覆盖 ESP32-P4 7B 板、FT-710 USB Host CAT 和当前五区界面的完整项目；可复用内容分散在板卡 BSP、FT-710 CAT 控制器、Yaesu Web 控制器和 CP210x USB Host 组件中。

### 分析依据与决策摘要

- Windows 识别 FT-710 为 CP2105 双串口：`COM5 Enhanced COM Port` 和 `COM6 Standard COM Port`。

- Windows 可获取 FT-710 USB Audio 输入，并实时播放到 Realtek 扬声器；用户确认监听结果正常。
- 对 ESP32-P4 下一步开发的直接意义：先复现 CP2105 Enhanced 接口枚举与 `ID; FA; MD0; PC;` 最小闭环，USB Audio 暂列为后续功能。

## 9. ESP32-P4 直连 FT-710 USB Host 实测

### 用户提问

> 好的，现在已经将FT-710接到了ESP

### 已交付回答

建立并烧写了 `D:\CAT CONTROL\ft710_usb_probe`，用于 ESP32-P4 直连 FT-710 的 USB Host CAT 探测。详细记录见 [[09_ESP32P4直连FT710_USBHost实测记录]]。

### 分析依据与决策摘要

- 固件只尝试打开 CP210x VCP 并发送安全只读 CAT 命令，不发送 PTT 或发射相关命令。
- 第一次运行确认默认未启用外部 Hub 支持，随后启用 `CONFIG_USB_HOST_HUBS_SUPPORTED=y` 并重新构建、刷写。
- 启用 Hub 支持后，ESP32-P4 已经能看到 FT-710 USB 路径中的 Hub。
- ESP-IDF v5.5.5 随后报错 `Connected device is FS, transaction translator (TT) is not supported`，导致下游 CP2105 无法枚举。
- 源码检查确认 ESP-IDF 当前 Hub 实现中 TT 相关路径未实现；失败点不是电脑侧 CAT、FT-710 串口参数或 CP210x 命令问题。
- 当前建议先确认 FT-710 USB 设备拓扑和 ESP-IDF TT 支持状态，再决定继续走 ESP32-P4 USB 直连、外置 USB Host 桥接，或改用其他 CAT 硬件链路。

## 10. ESP 端 FT-710 CAT 问题解决路线

### 用户提问

> 想办法解决这个问题

### 已交付回答

继续尝试了 ESP32-P4 USB 直连软件 workaround，并建立了 FT-710 CAT-3 UART 探针工程。详细记录见 [[10_ESP端FT710_CAT问题解决路线]]。

### 分析依据与决策摘要

- 尝试强制使用 ESP32-P4 OTG1.1 Full-Speed 根口，以期让 FT-710 USB Hub 避开 High-Speed TT 限制。
- Full-Speed 根口下故障从 TT 报错变为 `CHECK_SHORT_DEV_DESC FAILED`，说明绕行未成功。
- 追加根口 power-cycle 后仍无法读取短设备描述符。
- 判断继续在 ESP-IDF v5.5.5 内补 USB Host Hub/TT 不适合第一阶段主线。
- 建立 `D:\CAT CONTROL\ft710_uart_probe`，用于 FT-710 后面板 CAT-3 TTL UART 测试。
- UART 探针采用 UART1、TX GPIO27、RX GPIO26、38400 8N2，只发送 `ID; FA; FB; MD0; MD1; PC; NR0; RL0;` 等只读命令。
- `ft710_uart_probe` 已构建成功，待接入 5V TTL 到 3.3V TTL 电平转换后烧写实测。

- 底部键帽文字从 `CLR` / `BS` 改为 `CLEAR` / `BACK`。
- 修正版已完成 `idf.py build`、`idf.py -p COM4 flash` 和启动日志验证。
