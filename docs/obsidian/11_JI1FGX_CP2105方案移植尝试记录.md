# JI1FGX Yaesu CP2105 ESP32-S3 方案移植尝试记录

## 背景

用户询问网上是否已有 ESP32 通过 USB 控制/读取八重洲电台的例子。检索到 JI1FGX/DU9 的 Yaesu CP2105 ESP32-S3 项目：

- 页面：https://ji1fgx.com/en/260408.php
- 下载包：https://ji1fgx.com/files/20260518_Yaesu_CP2105_Driver_ESP32S3.zip
- 页面说明：ESP32-S3 USB Host 控制 Yaesu 电台，使用自定义 CP2105 driver，带 USB Hub 支持，作者测试对象包括 FT-891 与 FTDX3000。

本项目的目标对象是 FT-710 + Waveshare ESP32-P4-WIFI6-LCD-TOUCH-7B。FT-710 的 USB 侧实际拓扑包含 Hub，ESP-IDF v5.5.5 在 High-Speed Hub 下游 Full-Speed 设备处会报 TT 不支持，导致无法枚举到 CP2105 CAT 串口。

## 源码分析

下载并解压位置：

```text
D:\CAT CONTROL\third_party\ji1fgx_yaesu_cp2105_esp32s3_20260822_214641\Yaesu_CP2105_Driver_ESP32S3
```

关键观察：

- 主驱动位于 `main\Yaesu_CP2105_driver_Ver0.0.2.cpp`。
- 该驱动包含手写 CP2105 vendor control 与 bulk endpoint 读写逻辑。
- 源码中存在 Hub 辅助函数，例如 `hub_get_descriptor`、`hub_get_port_status`、`hub_reset_and_wait_port`。
- 但在 `yaesu_init()` 主初始化路径中，这些 Hub 辅助函数没有被真正调用。
- `managed_components\espressif__usb\src\hub.c` 内仍存在 ESP-IDF / espressif usb 组件的 TT 限制判断：

```text
Connected device is FS, transaction translator (TT) is not supported
```

初步判断：JI1FGX 方案的 CP2105 用户态驱动有参考价值，但它并没有提供完整的 High-Speed Hub Transaction Translator 支持。它能否工作取决于具体电台/Hub/芯片拓扑；不能直接证明 ESP32-P4 可以枚举 FT-710 内置 Hub 下游 CP2105。

## 移植试验

新建实验工程：

```text
D:\CAT CONTROL\ft710_ji1fgx_probe
```

工程基础：

- 由 `D:\CAT CONTROL\ft710_usb_probe` 复制得到。
- 继续使用 ESP-IDF v5.5.5。
- Target：`esp32p4`。
- 烧写/日志串口：`COM4`。
- USB 模式：ESP32-P4 默认 High-Speed root port。
- 不发送 PTT/TX 命令，只尝试打开 CP2105 Enhanced VCP 并发送安全只读查询。

移植内容：

- 将 JI1FGX 包中的 `managed_components\espressif__usb` 放入实验工程，以便覆盖 ESP-IDF 内置 `usb` 组件。
- `main\idf_component.yml` 加入：

```yaml
dependencies:
  espressif/usb: "*"
```

- 修改本地 `managed_components\espressif__usb\src\hub.c`，把遇到 HS Hub 下游 FS 设备时的硬失败改成继续尝试枚举：

```text
W HUB: Trial: continuing enumeration for FS device behind HS hub without explicit TT support
```

## 结论

这次试验证明：

- 本地覆盖的 USB Hub 组件确实进入固件，`Trial:` 日志已出现。
- 仅移除/绕过 ESP-IDF Hub 层的 TT 检查不足以解决 FT-710 枚举问题。
- 在 ESP32-P4 + FT-710 这个拓扑下，控制传输仍然失败于 `CHECK_SHORT_DEV_DESC`。
- 失败位置已经从“Hub 层主动拒绝”推进到“枚举控制传输失败”，说明下层 HCD/USB Host 仍缺少对 High-Speed Hub Transaction Translator 的真实支持。
- JI1FGX 项目的 CP2105 用户态驱动可作为以后写 Yaesu/CP2105 专用驱动的参考，但当前不能作为 FT-710 USB 直连 ESP32-P4 的可用解决方案。

## 当前路线调整

短期主线应继续改走 FT-710 后面板 CAT-3 TTL UART：

- 避开 FT-710 USB Composite/Hub/CP2105 拓扑。
- 避开 ESP-IDF 当前 USB Host Hub/TT 限制。
- 使用已建立的 `D:\CAT CONTROL\ft710_uart_probe` 验证 `ID; FA; FB; MD0; MD1; PC; NR0; RL0;`。
- 必须通过 5V TTL <-> 3.3V TTL 电平转换或隔离模块连接，不能把 FT-710 CAT-3 5V TTL 直接接 ESP32-P4 GPIO。

USB Host 路线可以保留为后续研究分支，前提是：

- 乐鑫官方 USB Host 提供真正的 TT 支持；或
- 移植第三方/自研完整 TT 调度能力；或
- 找到可让 FT-710 内置 Hub 不以 HS Hub 下游 FS 设备形态暴露 CP2105 的硬件拓扑。
