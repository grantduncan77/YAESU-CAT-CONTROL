# ESP32-P4 CH9102 写入控制与最小 UI 实测记录

## 本次目标

在 [[12_ESP32P4_CH9102_USBTTL_CAT3实测记录]] 已确认 ESP32-P4 可通过外置 CH9102 USB-TTL 读取 FT-710 CAT-3 状态的基础上，继续验证以下内容：

1. ESP32-P4 是否可以稳定向 FT-710 写入 CAT 命令。
2. 写入频率、模式、DNR 开关和 DNR 等级后，电台是否有正常反应。
3. 在 ESP32-P4 触摸屏上做一个尽量简单的实时显示界面，观察轮询时间是否可接受。
4. 在该界面上加入数字键盘，用于触摸输入频率并写入 VFO-A 或 VFO-B。

用户约束：

- 本项目主线使用 VSCode + ESP-IDF。
- 不使用 Arduino。
- 现阶段尽量避免过大的 UI 工程改动。
- 可以先用最小界面做通信和响应速度测试。

## 硬件链路

当前采用的可行链路：

```text
FT-710 CAT-3 TTL UART
    -> 外置 CH9102 USB-TTL
    -> ESP32-P4 USB Host
    -> ESP-IDF usb_host_cdc_acm
    -> LVGL 触摸 UI
```

关键参数：

```text
CH9102 VID:PID = 1A86:55D4
串口参数 = 38400 8N1
流控 = 无
RTS/DTR = false
ESP32-P4 下载/日志串口 = COM4
ESP-IDF = v5.5.5
目标芯片 = esp32p4
实测芯片 = ESP32-P4 rev v1.3
```

说明：

- FT-710 后 USB Type-B 直连 ESP32-P4 的路线暂时受内置 USB Hub/CP2105/TT 限制阻塞。
- 当前第一阶段主线改为外置 CH9102 + CAT-3。
- ESP32-P4 仍然作为 USB Host，只是枚举对象从 FT-710 内置 CP2105 改为外置 CH9102。

## CAT 写入控制测试

### 测试命令

在 `ft710_ch9102_usb_probe` 中加入写入与回读验证。

初始读取：

```text
ID;
FA;
FB;
MD0;
MD1;
NR0;
RL0;
```

写入命令：

```text
FA007074000;   VFO-A = 7.074000 MHz
FB014270000;   VFO-B = 14.270000 MHz
MD02;          VFO-A = USB
MD11;          VFO-B = LSB
NR01;          DNR = ON
RL007;         DNR level = 7
```

回读验证：

```text
FA;
FB;
MD0;
MD1;
NR0;
RL0;
```

### 实测结果

初始读取：

```text
ID;  -> ID0800;       4 ms
FA;  -> FA008999000;  5 ms
FB;  -> FB028400000;  5 ms
MD0; -> MD05;         3 ms
MD1; -> MD11;         3 ms
NR0; -> NR01;         3 ms
RL0; -> RL007;        3 ms
```

写入后回读：

```text
FA;  -> FA007073300;  7 ms
FB;  -> FB014270000;  5 ms
MD0; -> MD02;         3 ms
MD1; -> MD11;         3 ms
NR0; -> NR01;         3 ms
RL0; -> RL007;        3 ms
```

探针结果：

```text
Probe finished: initial 7/7, verify 6/6
```

### 结论

- ESP32-P4 通过 CH9102 + CAT-3 可以成功写入 FT-710。
- VFO-B 频率写入正常。
- VFO-A 模式写入 USB 正常。
- VFO-B 模式写入 LSB 正常。
- DNR 打开正常。
- DNR level 7 设置和读取正常。
- CAT 单条读响应大多在 `3-7 ms`。
- 写命令后等待约 `179 ms` 再回读，电台状态已更新。

注意事项：

- 本轮 `FA007074000;` 后回读为 `FA007073300;`，与目标频率相差 `700 Hz`。
- 这可能与当前电台状态、模式切换顺序、步进、RIT/偏移或测试时旋钮状态有关。
- 后续应单独做“先设模式再设频率”和“确认 RIT/CLAR/步进状态”的复测。
- 不影响本次“ESP 到 FT-710 写命令链路可用”的结论。

## 最小频率显示界面测试

### 第一版：只显示 VFO-A

用户提出先做最简单界面，只显示频率，用于观察 FT-710 上频率改变后 ESP32-P4 是否能快速显示。

实现方式：

- 启动 BSP 显示和 LVGL。
- 打开 CH9102 `VID:PID 1A86:55D4`。
- 设置 `38400 8N1`。
- 每 `100 ms` 发送 `FA;`。
- 解析 `FAxxxxxxxxx;`。
- 仅在频率变化时更新 LVGL label 并打印日志。

屏幕内容：

```text
FT-710 VFO-A
<VFO-A frequency> MHz
OK <ms> poll 100 ms #<count>
```

实测日志节选：

```text
CH9102 opened, polling FA; every 100 ms
VFO-A changed: 7.073300 MHz raw=FA007073300; elapsed=5 ms
```

用户转动 FT-710 频率旋钮时，ESP 日志连续捕获变化：

```text
VFO-A changed: 7.075800 MHz raw=FA007075800; elapsed=5 ms
VFO-A changed: 7.078000 MHz raw=FA007078000; elapsed=5 ms
...
VFO-A changed: 5.959000 MHz raw=FA005959000; elapsed=5 ms
```

观察结论：

- `100 ms` 轮询可以接受。
- CAT 响应通常 `4-5 ms`。
- 实际频率变化捕获间隔约 `105 ms`。
- 未观察到持续 timeout 或断连。

## 双 VFO 频率显示

用户确认 `100 ms` 可接受后，要求同时显示 VFO-A 和 VFO-B 频率。

实现方式：

- 屏幕上方显示 `VFO-A` 当前频率。
- 屏幕第二行显示 `VFO-B` 当前频率。
- 后台轮询每轮顺序读取：

```text
FA;
FB;
```

轮询节奏：

```text
FA 查询约 4-5 ms
FB 查询约 4-5 ms
每轮之后延时 100 ms
实际完整周期约 110 ms
```

屏幕内容：

```text

VFO-A  x.xxxxxx MHz
VFO-B  x.xxxxxx MHz

OK A:<ms> B:<ms> poll 100 ms #<count>
```

首次启动实测：

```text

VFO-A changed: 9.570000 MHz raw=FA009570000; elapsed=5 ms
VFO-B changed: 14.403600 MHz raw=FB014403600; elapsed=5 ms
```

转动 VFO-A 时，连续变化捕获正常：

```text
VFO-A changed: 9.581000 MHz raw=FA009581000; elapsed=5 ms
VFO-A changed: 9.592000 MHz raw=FA009592000; elapsed=5 ms
VFO-A changed: 9.600000 MHz raw=FA009600000; elapsed=5 ms
...
VFO-A changed: 9.949000 MHz raw=FA009949000; elapsed=5 ms
```

结论：

- 双 VFO 轮询仍然流畅。
- 单条 CAT 响应依旧稳定在约 `4-5 ms`。
- 两路轮询实际刷新节奏约 `110 ms`。
- 作为第一阶段状态显示完全可接受。

## 数字键盘频率设置测试

### 用户需求

在双 VFO 显示界面上加入数字键盘，用于直接改变频率测试。

### UI 布局

最终屏幕包含：

```text
FT-710

VFO-A  x.xxxxxx MHz
VFO-B  x.xxxxxx MHz

Target VFO-A
A  --.------ MHz

7   8   9   A
4   5   6   B
1   2   3   BS
.   0   CLR SET

状态栏
```

按钮含义：

```text
A     选择 VFO-A 作为写入目标
B     选择 VFO-B 作为写入目标
0-9   输入频率数字
.     输入 MHz 小数点
BS    删除最后一位
CLR   清空输入
SET   发送频率设置命令
```

输入规则：

- 输入单位为 MHz。
- 允许小数点。
- 小数部分最多按 `6` 位 MHz 小数转换，也就是 Hz 精度。
- 例如输入 `14.2700` 会转换为 `14.270000 MHz`。
- CAT 命令自动补成 9 位 Hz 字段：

```text
14.2700 -> 14270000 Hz -> FA014270000; 或 FB014270000;
```

### 线程与队列设计

为避免触摸事件和后台轮询同时操作同一个 CH9102 句柄，采用队列方式：

```text
LVGL 触摸事件
    -> 解析输入
    -> 投递 set_freq_request_t 到 s_set_queue
    -> cat_poll_task 中取出请求
    -> 发送 FA/FB 写命令
    -> 下一轮 FA/FB 轮询回读确认
```

关键原因：

- USB/CAT 读写集中在 `cat_poll_task`。
- LVGL 事件回调不直接访问 `cdc_acm_dev_hdl_t`。
- 后续扩展模式、DNR、功率命令时也可复用同一命令队列。

### 写命令处理

设置频率时生成命令：

```text
VFO-A: FA%09d;
VFO-B: FB%09d;
```

示例：

```text
1.236000 MHz -> FA001236000;
7.890000 MHz -> FB007890000;
```

重要实现细节：

- FT-710 的频率设置命令通常不会回包。
- 因此 `SET` 后不等待 CAT 响应作为成功依据。
- 程序只确认 USB TX 成功。
- 真正的成功确认来自下一轮 `FA;` 或 `FB;` 回读。

### 防重复发送修正

第一次触摸测试中，观察到 `SET` 可能连续触发多次，日志中出现多次相同命令：

```text
Set VFO-B to 12.369572 MHz cmd=FB012369572; elapsed=0 ms
Set VFO-B to 12.369572 MHz cmd=FB012369572; elapsed=0 ms
...
```

随后加入防护：

- `SET` 成功入队后立即清空输入框。
- 即使触摸重复命中，也不会反复发送同一个输入值。

## 当前结论

本轮测试确认：

- ESP32-P4 + 外置 CH9102 + FT-710 CAT-3 不仅可以读取状态，也可以可靠写入控制命令。
- 频率写入已通过 VFO-A 和 VFO-B 双路验证。
- 模式写入已通过 VFO-A/VFO-B 验证。
- DNR 开关和等级写入已验证。
- 双 VFO 轮询显示在 `100 ms` 设置下可接受。
- LVGL 触摸键盘可完成从屏幕输入到 CAT 写频率再到电台回读确认的闭环。
- 当前链路已经足够支撑第一阶段正式 UI 和状态机开发。

## 后续建议

1. 将当前示例中的 CAT 代码抽出为正式 `CatTransport` 组件。
2. 将 UI 与 CAT 逻辑拆分，形成 `ui`、`radio_state`、`cat_transport`、`command_queue` 几个边界。
3. 对所有写命令建立白名单，初期继续禁止 PTT。
4. 做频率合法范围校验，避免输入超出 FT-710 支持范围。
5. 增加模式、DNR、功率的触摸控制，并继续采用“发送命令后轮询回读确认”的策略。
6. 做长时间轮询测试，至少覆盖 30 分钟、1 小时和电台开关机/USB 热插拔场景。
7. 单独复测 `FA007074000;` 回读偏 `700 Hz` 的现象，确认是否由模式、RIT/CLAR、步进或测试过程造成。
