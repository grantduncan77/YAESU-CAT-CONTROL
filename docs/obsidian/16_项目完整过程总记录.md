# FT-710 CAT Control 项目完整过程总记录

## 记录目的

本文用于集中记录本项目从规划、设计、试验、开发、纠错到当前实现状态的完整过程。

详细技术过程分散在 `00` 到 `15` 号文档中，本文作为总档案：

- 串起完整时间线。
- 记录关键决策为何发生。
- 保留失败路线和纠错依据。
- 归档期间生成和反馈使用的界面、原型、截图和实机照片。
- 标注当前已实现、已验证、待确认和后续重构方向。

## 1. 项目起点与总体目标

本项目目标是为 YAESU FT-710 制作一个外置扩展触摸控制器。

目标硬件：

- Waveshare ESP32-P4-WIFI6-LCD-TOUCH-7B
- 7 英寸 1024 × 600 横屏
- ESP32-P4 主控
- 板载 ESP32-C6 作为 WiFi/BLE 协处理器
- GT911 电容触摸
- MIPI-DSI LCD

初始软件路线：

- VSCode + ESP-IDF
- 不使用 Arduino 作为正式主线
- LVGL 作为 GUI 框架
- CAT 协议控制 FT-710

第一阶段功能范围：

- 显示 VFO-A / VFO-B 频率
- 直接输入频率
- 切换 VFO-A / VFO-B 输入目标
- 执行 A/B 工作状态切换
- 设置 Mode
- 设置 Band 默认频率
- 设置 RF Power
- 设置 DNR 开关和等级
- 显示 CAT、BT、WiFi、RX 等状态
- 不实现 PTT

关键安全边界：

- 初代不做发射控制。
- 不做 PTT。
- 所有写入功能先从频率、模式、功率、DNR 等非发射动作开始。
- CAT 写入后以电台回读为最终状态来源。

## 2. 早期界面原型

最初设计目标不是做一个普通网页，而是做一个适合 7 英寸电容触摸屏的“电台扩展面板”。

主视觉方向：

- 深色底。
- 青色高亮。
- 细线框分区。
- 横屏仪表式布局。
- 大数字频率显示。
- 大面积触摸按钮。
- 尽量少用解释性文字，直接呈现控制面板。

在线原型：

```text
https://ft710-touch-controller.xun-ke-7448.chatgpt.site/
```

首版原型图：

![[assets/ui_main_original_reference.png]]

首版原型包含：

- 左侧大频率显示区。
- 左侧 Direct Frequency 数字键盘。
- 中间 RF Power 面板。
- 中间 Mode 面板。
- 右侧 DNR 面板。
- 右下 Band 面板。

此阶段形成的核心界面原则：

- 页面必须横屏。
- 频率输入区域不能占据过多宽度，后续缩小到约 40%。
- VFO-A / VFO-B 需要上下两行显示。
- 顶部必须留状态栏，为 CAT、BT、WiFi、RX、菜单、时间等后续功能留位置。
- DNR 的 `+/-` 要明显加大，方便触摸。
- 功率数值和单位 `W` 应在同一行显示，避免浪费纵向空间。
- Band 数字要足够大，便于快速点击。

## 4. FT-710 电脑侧 CAT 和 USB Audio 基准测试

在接入 ESP32-P4 前，先用本电脑直连 FT-710 做基准测试。

目的：

- 确认 FT-710 本身 CAT 通信正常。
- 确认 CAT 命令、串口参数和电台状态响应可用。
- 确认 USB Audio 可在电脑端正常接收。

电脑侧 CAT：

- FT-710 通过 USB 直接连接电脑。
- 使用 Enhanced COM Port。
- 关键返回：`ID0800;`
- 说明电台可通过 CAT 正常响应。

已验证动作：

- 读取频率。
- VFO-A 设置为 `14.270000 MHz`。
- VFO-B 设置为 `21.400000 MHz`。
- VFO-A 模式设置为 USB。
- VFO-B 模式设置为 USB。
- 打开 DNR。
- 设置 DNR level。
- 读取 DNR 当前值。

USB Audio：

- Windows 可获取 FT-710 USB Audio 输入。
- 可播放到本电脑扬声器。
- 用户确认监听结果正常。

此阶段结论：

- 电脑与 FT-710 的 CAT 通信完全正常。
- FT-710 USB Audio 输入链路正常。
- 后续 ESP 端问题若出现，应优先怀疑 ESP USB Host/Hub/驱动路径，而不是 FT-710 CAT 参数。

## 5. ESP32-P4 直连 FT-710 USB Host 尝试

初始期望是让 ESP32-P4 直接通过 USB Host 连接 FT-710 后 USB 口，并枚举 FT-710 内部 CP2105 CAT 串口。

测试工程：

```text
D:\CAT CONTROL\ft710_usb_probe
```

测试目标：

- 枚举 FT-710 USB 设备。
- 找到 CP2105 Enhanced CAT 接口。
- 发送安全只读 CAT 查询。

实测结果：

- ESP32-P4 能看到 FT-710 USB 路径中的 Hub。
- 启用 `CONFIG_USB_HOST_HUBS_SUPPORTED=y` 后，仍无法枚举下游 CP2105。
- ESP-IDF v5.5.5 报错：

```text
Connected device is FS, transaction translator (TT) is not supported
```

技术判断：

- FT-710 USB 路径中存在 High-Speed Hub。
- CP2105 是 Full-Speed 下游设备。
- ESP-IDF 当前 USB Host Hub 栈对 High-Speed Hub 下游 Full-Speed 设备所需的 Transaction Translator 支持不足。
- 问题不是 CP210x 驱动没有加载这么简单，而是 Hub/TT 级别限制。

## 6. ESP 端 USB 路线纠错与 JI1FGX 方案调研

为解决 FT-710 USB 直连问题，做过两条尝试：

1. 尝试 ESP32-P4 OTG1.1 Full-Speed 根口 workaround。
2. 参考 JI1FGX Yaesu CP2105 ESP32-S3 项目的 Hub/CP2105 方案。

OTG workaround：

- 尝试强制走 Full-Speed 根口。
- 尝试根口 power-cycle。
- 故障从 TT 报错变为 `CHECK_SHORT_DEV_DESC FAILED`。
- 未能稳定枚举 FT-710 下游 CP2105。

JI1FGX 方案分析：

- 目标项目思路是 ESP32-S3 通过 USB Host 控制 Yaesu 电台 CP2105。
- 本地建立移植探针：

```text
D:\CAT CONTROL\ft710_ji1fgx_probe
```

- 移植本地 `espressif__usb` 组件。
- 尝试绕过 TT 检查。
- 实机日志出现 `Trial:`，但随后失败于 `CHECK_SHORT_DEV_DESC`。

结论：

- 单纯绕过检查不足以解决 FT-710 USB 直连枚举。
- 在 ESP-IDF v5.5.5 下继续补完整 USB Host Hub/TT 不适合作为第一阶段主线。
- 第一阶段需要更简单可靠的物理 CAT 链路。

```text

  -> FT-710 CAT-3 TTL UART
```

电脑侧先测 CAT-3：

- 通过 TTL 转 USB 芯片把 CAT-3 接到电脑。
- COM7。
- 波特率 38400。
- 起始位 1。
- 停止位 1。
- 数据长度 8。

随后接入 ESP32-P4：

测试工程：

```text
D:\CAT CONTROL\ft710_ch9102_usb_probe
```

关键参数：

- CH9102 VID:PID `1A86:55D4`
- 串口 `38400 8N1`
- 使用 `usb_host_cdc_acm`

已验证读回：

```text

MD05;
MD11;
```

已验证写入：

- ESP32-P4 + 外置 CH9102 + FT-710 CAT-3 链路可用。

## 8. 最小 UI 与轮询试验

在正式界面前，先做最小显示界面验证 CAT 状态轮询速度。

用户要求：

- 现阶段可以不用 LVGL，避免编译时间过长。
- 最简单界面只显示频率。
- 看 FT-710 上频率改变后，ESP32-P4 是否能快速显示。
- `100 ms` 可以接受。
- 同时显示 VFO-A / VFO-B 频率。
- 后续加数字键盘测试改频率。

实测实现：

- 在 ESP32-P4 上显示 VFO-A / VFO-B 频率。
- 高频轮询 `FA;` / `FB;`。
- 目标轮询间隔约 `100 ms`。
- 单条 CAT 回读通常约 `4-7 ms`。
- 加入触摸数字键盘。
- 可选择 VFO-A 或 VFO-B。
- 输入 MHz 后发送 `FA%09d;` 或 `FB%09d;`。

实测结果：

```text
FA001236000; -> FA001236000;
FB007890000; -> FB007890000;
```

结论：

- 100 ms 双 VFO 轮询可接受。
- FT-710 上频率变化后，ESP32-P4 可以快速跟随显示。
- 触摸数字键盘写频可行。

用户反馈：

修正：

- 压缩数字键盘单键高度。
- 调整行距。
- 重新安排底部控制按钮位置。

### 10.2 DNR OFF 字体过大

用户反馈：

```text
NDR的OFF字体太大了
```

问题：

- `OFF` 在 DNR 面板中视觉过大，并靠近边界。

- DNR `OFF` 字体从大号降级。
- 调整位置，避免越界和压线。

### 10.3 功率/DNR 设置响应慢

用户反馈：

```text
功率，DNR设置时候反应太慢，特别是功率设置
```

原因：

- 初版界面更多依赖下一轮 CAT 慢轮询回读再刷新 UI。
- 用户点击后要等待回读更新，主观体验慢。

修正：

- 改为本地乐观更新。
- 触摸后立即更新 UI。
- 后台发送 CAT 命令。
- 后续轮询回读再校准真实状态。

功率命令改为明确目标：

```text
PCxxx;
```

实测日志：

```text

CAT set PC025; -> ESP_OK
CAT set PC015; -> ESP_OK
CAT set PC005; -> ESP_OK
```

## 12. 时间显示设计

时间显示需求来自 WiFi 联网之后。

用户要求：

```text
连接wifi后获取时间，并在状态标题栏中显示，要求点击一次显示本地时间，再点击一次显示UTC时间
```

进一步要求：

```text
时间显示无需做成按钮，直接显示在 CONTROL 和 现在按钮之间即可
```

```text
触摸或者点击这个时间区域切换UTC和本地时间显示
```

```text
字体加大，和FT-710 Control 一样大
```

```text
频率控制页面也是一样的要显示时间
```

最终设计：

- 时间显示是状态栏文本，不做明显按钮外观。
- 位置在 `FT-710 CONTROL` 和后续状态按钮之间。
- 用透明触摸区域承接点击事件。
- 点击时间区域切换本地时间 / UTC。
- 主频率控制页面和 WiFi 设置页面共用。
- 未联网或 SNTP 未同步时显示 `--:--:--`。

设计理由：

- 不占用主控制区。
- 保持状态栏仪表感。
- 时间属于高频查看信息，字体应接近标题级。
- 透明触摸区比纯文字更适合电容触摸。

```yaml
  version: "1.4.*"
```

这是因为：

- ESP32-P4 本身无 WiFi 射频。
- 目标板通过板载 ESP32-C6 做无线协处理器。
- ESP-Hosted / esp_wifi_remote 是 P4 使用 C6 WiFi 的桥接路径。

应用层 WiFi 模式：

```text
WIFI_MODE_STA
```

已实现：

- NVS 初始化。
- esp_netif 初始化。
- esp_event 初始化。
- ESP-Hosted WiFi 初始化。
- WiFi scan。
- AP 列表缓存。
- 点击 AP 复制 SSID。
- SSID/Password 输入。
- WiFi connect。
- WiFi disconnect。
- 获取 IP 地址。
- 获取 Gateway。
- 获取 DNS。
- SNTP 获取时间。
- 保存 SSID/Password。

## 14. 软键盘设计与修正

软键盘预览图：

![[assets/ui_wifi_keyboard_preview.png]]

软键盘打开状态曾出现重叠反馈：

![[assets/ui_wifi_keyboard_overlap_feedback.png]]

设计调整：

- 软键盘独立成页面。
- 不再在 WiFi 设置页面底部强行弹出。
- 键盘页面只显示当前编辑字段和键盘。
- `DONE` 后返回 WiFi 页面。
- `CANCEL` 返回 WiFi 页面。

用户后续反馈：

```text
软键盘缺少回删键，clr 不是清除所有，是c  bs也不是回删 是b
```

问题根因：

```c
strncmp(id, "K_", 2) == 0
```

这个通用分支先于控制键分支执行，导致：

- `K_CLR` 被当成字符输入，输入 `C`。
- `K_BS` 被当成字符输入，输入 `B`。
- `K_SPACE` 也可能被当成字符输入，输入 `S`。

修正：

- 控制键优先处理。
- 普通字符最后处理。

修正后顺序：

1. `K_SHIFT`
2. `K_SPACE`
3. `K_BS`
4. `K_CLR`
5. 普通 `K_` 字符

按钮文字：

- `CLR` 改为 `CLEAR`
- `BS` 改为 `BACK`

验证：

- `idf.py build` 通过。
- `idf.py -p COM4 flash` 成功。
- 启动日志确认 LCD、触摸、CAT、WiFi 均正常启动。

## 18. 当前主要限制与风险

1. `app_controller.c` 过大，UI、CAT、WiFi、时间、状态机混在一起。
2. CH9102 断线重连还需要完善。
3. WiFi 自动重连、连接失败提示、密码保存策略还需要完善。
4. AP 扫描缓存当前最多 16 个。
5. WiFi 连接后的真实网络连通、SNTP 同步仍需要用户实机确认。
6. LVGL lock 偶发日志需要继续观察。
7. FT-710 后 USB 直连 CP2105 仍受 Hub/TT 问题阻挡。
8. 当前 Band 是项目默认频率直写，不是 FT-710 Band Stack。
9. 本地乐观更新需要增加 pending/confirmed 状态，避免用户误以为电台已经接受命令。
10. 长时间运行稳定性、热插拔和射频环境抗扰还未完成。

## 19. 建议后续重构计划

建议从当前单文件实现拆分为以下模块：

```text
components/
  cat_transport_ch9102/
  ft710_cat/
  radio_state/
  ui_main/
  ui_wifi/
  ui_keyboard/
  wifi_manager/
  time_service/
  settings/
  diagnostics/
```

拆分顺序建议：

1. 先抽出 `ft710_cat`：命令格式化、响应解析、模式/功率/DNR 映射。
2. 再抽出 `cat_transport_ch9102`：USB CDC ACM 打开、读写、超时、重连。
3. 抽出 `radio_state`：集中保存 VFO、模式、功率、DNR、连接状态。
4. 抽出 `ui_main`：主控制页面渲染和事件。
5. 抽出 `ui_wifi` / `ui_keyboard`：WiFi 设置和输入法。
6. 抽出 `wifi_manager`：扫描、连接、断开、NVS 保存。
7. 抽出 `time_service`：SNTP、UTC/local 切换、格式化。
8. 最后加入 diagnostics/log 页面，用于现场调试。
