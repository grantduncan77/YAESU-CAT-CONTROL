# 主程序功率旋钮无效排查与修正

## 用户反馈

在将 TCA9548A channel 3 上的 0.96 寸 SSD1306 OLED 功率显示合入主程序后，用户反馈：

> 旋钮无效

后续在调试过程中，用户进一步指出：

> 刚刚清理之前正常，清理后旋钮又无效

这里的“旋钮”主要指 MCP23017 上的 RF Power EC11 旋钮：

| EC11 引脚 | MCP23017 引脚 | 功能 |
| --- | --- | --- |
| A | PA6 | 功率旋钮 A 相 |
| B | PA7 | 功率旋钮 B 相 |
| S | PB0 | 功率旋钮按键 |

预期行为：

- 旋钮每一档改变 RF Power `1 W`
- 发送 FT-710 CAT `PCxxx;` 命令
- 主界面 RF Power 数值更新
- 辅助 OLED 跟随 `s_state.power_w` 显示功率

## 第一次复现

重新 build/flash/monitor 主程序后，启动日志显示 OLED 初始化成功，但 MCP23017 初始化失败：

```text
E ft710_controller: encoder_mcp23017_init(...): set MCP23017 IODIRA
W ft710_controller: External encoder disabled; check I2C wiring and MCP23017 address jumpers
I ft710_controller: Aux OLED ready: TCA9548A=0x70 channel=3 SSD1306=0x3C
```

这个现象说明：

- TCA9548A 与 SSD1306 OLED 在主程序中可以初始化
- 编码器任务在配置 MCP23017 `IODIRA` 时失败
- 旋钮无效不是四相解码问题，而是 MCP23017 没有成功进入工作状态

## 初步修正：启动顺序和 OLED 独立任务

为了避免 OLED 刷新和 MCP23017 读写互相抢 I2C，总线访问被统一放到 mutex 保护之下。

同时将辅助 OLED 改为独立任务：

- 主 UI 刷新不再直接整屏刷新 OLED
- `aux_oled_task` 每 `100 ms` 检查 `s_state.power_w`
- OLED 任务启动前延迟 `500 ms`
- 编码器任务优先创建，OLED 任务后创建
- OLED 任务优先级降低

这样可以让 MCP23017 先完成配置，再启动 TCA9548A/OLED。

## 第二次复现：地址误判

第一次启动顺序修正后，调试版曾经正常工作：

```text
I ft710_controller: MCP23017 candidate detected at 0x27, configuring at 100000 Hz
I ft710_controller: MCP23017 encoder detected at 0x27, freq A=PA0 B=PA1 S=PA2 step=1000 Hz, power A=PA6 B=PA7 S=PB0 step=1 W
I ft710_controller: MCP23017 initial GPIOA=0xC7 GPIOB=0x01 freq_ab=3 power_ab=3
I ft710_controller: Aux OLED ready: TCA9548A=0x70 channel=3 SSD1306=0x3C
```

旋转功率旋钮时，串口捕获到 PA6/PA7 四相边沿，并发送了 PC 命令：

```text
I ft710_controller: CAT set PC012; -> ESP_OK (0 ms)
I ft710_controller: CAT set PC011; -> ESP_OK (0 ms)
I ft710_controller: CAT set PC010; -> ESP_OK (0 ms)
I ft710_controller: CAT set PC009; -> ESP_OK (0 ms)
I ft710_controller: CAT set PC008; -> ESP_OK (0 ms)
I ft710_controller: CAT set PC007; -> ESP_OK (0 ms)
```

但清理日志后的正式版再次出现失效。再次 monitor 后发现初始化先命中了 `0x22`：

```text
I ft710_controller: MCP23017 candidate detected at 0x22, configuring at 100000 Hz
W ft710_controller: MCP23017 write IODIRA reg=0x00 value=0xFF failed attempt 1: ESP_ERR_INVALID_STATE
W ft710_controller: MCP23017 write IODIRA reg=0x00 value=0xFF failed attempt 2: ESP_ERR_INVALID_STATE
W ft710_controller: MCP23017 write IODIRA reg=0x00 value=0xFF failed attempt 3: ESP_ERR_INVALID_STATE
E ft710_controller: encoder_mcp23017_init(...): set MCP23017 IODIRA
W ft710_controller: External encoder disabled; check I2C wiring and MCP23017 address jumpers
```

关键结论：

- 独立测试和正常调试版中的 MCP23017 实测地址是 `0x27`
- 主程序按 `0x20..0x27` 顺序扫描时，偶发先拿到了错误候选地址 `0x22`
- TCA9548A channel 状态、下游设备或总线瞬态 ACK 可能导致地址扫描被误导
- 只要 MCP23017 没有配置成功，编码器任务会退出，所以旋钮完全无效

## 最终修正

### 1. 统一辅助 I2C 速率为 100 kHz

独立 OLED/MCP 测试中稳定工作的 I2C 速率为 `100 kHz`。主程序原先 MCP23017 使用 BSP 默认 I2C 速率，可能高于 100 kHz。

修正为：

```c
#define AUX_I2C_HZ 100000
```

TCA9548A、SSD1306、MCP23017 都使用 `AUX_I2C_HZ`。

### 2. MCP23017 地址优先验证 0x27

不再简单接受第一个 ACK 地址。

新的候选顺序：

```c
const uint8_t candidates[] = {0x27, 0x20, 0x21, 0x22, 0x23, 0x24, 0x25, 0x26};
```

流程：

1. 优先探测 `0x27`
2. add device
3. 配置 `IODIRA/GPPUA/IODIRB/GPPUB`
4. 只有寄存器写入全部成功，才接受该地址为 MCP23017
5. 如果配置失败，移除该 device handle，继续尝试下一个候选地址

### 3. 写寄存器增加重试和错误日志

新增 `mcp23017_write_reg_retry()`：

- 每个关键寄存器最多写 3 次
- 每次失败打印寄存器、写入值、尝试次数和错误码
- 有助于区分地址误判、I2C 状态错误、总线忙或硬件连接问题

### 4. 功率旋钮改为全局可用

原逻辑中 `encoder_adjust_power()` 会在非主界面直接返回。为避免页面状态导致硬件旋钮被静默忽略，功率旋钮改为不受当前页面限制：

- `delta == 0` 才忽略
- 任意页面下都可以发送 RF Power `PCxxx;`
- 只有当前处于主界面时才刷新主屏 RF Power 区域
- 辅助 OLED 仍由后台任务跟随 `s_state.power_w` 刷新

### 5. 保留低频有效动作日志

最终版不再打印每个四相边沿，只在形成一个有效功率档位时打印：

```text
Power encoder set xxW
```

这样既能现场确认旋钮动作，又不会刷屏影响观察。

## 最终验证

最终 build/flash/monitor 成功。

启动日志：

```text
I ft710_controller: MCP23017 candidate detected at 0x27, configuring at 100000 Hz
I ft710_controller: MCP23017 encoder detected at 0x27, freq A=PA0 B=PA1 S=PA2 step=1000 Hz, power A=PA6 B=PA7 S=PB0 step=1 W
I ft710_controller: MCP23017 initial GPIOA=0xC7 GPIOB=0x01 freq_ab=3 power_ab=3
I ft710_controller: CH9102 opened, FT-710 control UI running
I ft710_controller: Aux OLED ready: TCA9548A=0x70 channel=3 SSD1306=0x3C
```

旋转功率旋钮后，捕获到有效功率步进和 CAT 命令：

```text
I ft710_controller: Power encoder set 14W
I ft710_controller: CAT set PC014; -> ESP_OK (0 ms)
I ft710_controller: Power encoder set 15W
I ft710_controller: CAT set PC015; -> ESP_OK (0 ms)
I ft710_controller: Power encoder set 16W
I ft710_controller: CAT set PC016; -> ESP_OK (0 ms)
I ft710_controller: Power encoder set 17W
I ft710_controller: CAT set PC017; -> ESP_OK (0 ms)
I ft710_controller: Power encoder set 18W
I ft710_controller: CAT set PC018; -> ESP_OK (0 ms)
```

验证结论：

- MCP23017 在主程序中稳定使用 `0x27`
- RF Power EC11 旋钮 PA6/PA7 输入有效
- 每档 `1 W` 步进有效
- FT-710 CAT `PCxxx;` 命令发送成功
- CH9102 CAT 链路正常
- SSD1306 辅助 OLED 初始化正常
- 去除每边沿调试日志后，旋钮仍可工作

## 仍需注意

本次日志中仍能看到：

```text
E transport: Not able to connect with ESP-Hosted slave device
```

这属于 ESP-Hosted WiFi 从机连接问题，与当前 MCP23017 旋钮、CH9102 CAT、TCA9548A/OLED 不是同一条功能链路。本次旋钮修正不依赖 WiFi 成功。

## 代码变更摘要

主文件：

```text
D:\CAT CONTROL\ft710_controller\components\app_controller\app_controller.c
```

主要变更：

- `AUX_OLED_I2C_HZ` 改为通用 `AUX_I2C_HZ`
- TCA9548A、SSD1306、MCP23017 均使用 `100 kHz`
- 新增 MCP23017 写寄存器重试
- MCP23017 初始化改为优先验证 `0x27`
- 候选地址必须完整配置成功才被接受
- OLED 刷新改为 `aux_oled_task`
- 编码器任务先于 OLED 任务启动
- 功率旋钮全局可用
- 保留有效功率步进日志 `Power encoder set xxW`
