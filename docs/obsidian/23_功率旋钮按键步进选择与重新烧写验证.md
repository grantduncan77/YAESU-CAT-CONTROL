# 功率旋钮按键步进选择与重新烧写验证

## 背景

本阶段是在主程序已经集成第二个 EC11 功率旋钮、MCP23017 I/O 扩展、TCA9548A Qwiic Mux、0.96 寸 SSD1306 辅助 OLED 后继续完善功率旋钮操作。

已有硬件定义：

- MCP23017 地址：`0x27`
- 频率旋钮：A=`PA0`，B=`PA1`，S=`PA2`
- 功率旋钮：A=`PA6`，B=`PA7`，S=`PB0`
- TCA9548A 地址：`0x70`
- 0.96 寸 SSD1306 OLED：TCA9548A channel `3`，OLED 地址 `0x3C`
- ESP32-P4 烧写口本次实测为：`COM4 USB-Enhanced-SERIAL CH343`

## 助手可见回复与处理过程整理

### 1. 重新上传固件前检查

助手先确认当前工程状态和可用串口：

- `git status --short`
- `Get-CimInstance Win32_SerialPort`
- 检查 `sdkconfig` / `sdkconfig.defaults` / `build/config/sdkconfig.h` 中的 ESP-Hosted slave target 配置

发现：

- 工作区已有未提交代码：`ft710_controller/components/app_controller/app_controller.c`
- `ft710_controller/sdkconfig` 被 CMake 改成了错误状态
- `CONFIG_ESP_HOSTED_IDF_SLAVE_TARGET="invalid"`
- `CONFIG_IDF_SLAVE_TARGET="invalid"`
- Windows 当时可见 `COM9`，但后续烧写失败，实际可用烧写口为 `COM4`

助手说明：

> 当前电脑只看到 COM9。另外看到了上次 CMake 把 ESP-Hosted 从设备目标写成 invalid，这会导致重新构建失败；先把配置固化到 defaults，再重新生成固件并烧到串口。

### 2. 构建配置问题排查

最初尝试将 ESP32-C6 WiFi remote/Hosted 目标写入 `sdkconfig.defaults`：

```ini
CONFIG_ESP_HOSTED_PRIV_SDIO_OPTION=y
CONFIG_ESP_HOSTED_IDF_SLAVE_TARGET="esp32c6"
CONFIG_ESP_HOSTED_SPI_FREQ_ESP32C6=40
CONFIG_ESP_HOSTED_SPI_CLK_FREQ=40
CONFIG_ESP_WIFI_REMOTE_IDF_SPECIFIC_ADDED=y
# CONFIG_SLAVE_IDF_TARGET_ESP32 is not set
# CONFIG_SLAVE_IDF_TARGET_ESP32S2 is not set
# CONFIG_SLAVE_IDF_TARGET_ESP32C3 is not set
# CONFIG_SLAVE_IDF_TARGET_ESP32S3 is not set
# CONFIG_SLAVE_IDF_TARGET_ESP32C2 is not set
CONFIG_SLAVE_IDF_TARGET_ESP32C6=y
# CONFIG_SLAVE_IDF_TARGET_ESP32C5 is not set
# CONFIG_SLAVE_IDF_TARGET_ESP32C61 is not set
CONFIG_IDF_SLAVE_TARGET="esp32c6"
```

第一次重新构建仍失败，报错：

```text
esp_hosted_config.h:59:2: error: #error "Unknown Slave Target"
```

进一步检查 `managed_components/espressif__esp_wifi_remote/Kconfig` 后发现：

- `esp_wifi_remote` 通过 `orsource "./Kconfig.idf_v$ESP_IDF_VERSION.in"` 加载版本相关 Kconfig
- 当前构建命令没有设置 `ESP_IDF_VERSION`
- 因此 `SLAVE_IDF_TARGET_ESP32C6` 一组配置没有被 Kconfig 加载
- `sdkconfig.defaults` 中这些配置被提示为 unknown
- 最终导致 `esp_hosted_config.h` 看不到 `CONFIG_SLAVE_IDF_TARGET_ESP32C6`

修正方式：

```powershell
$env:ESP_IDF_VERSION='5.5'
```

同时移除了 defaults 里的旧名：

```ini
CONFIG_IDF_SLAVE_TARGET="esp32c6"
```

因为 CMake 提示该旧名会被替换为：

```ini
CONFIG_ESP_HOSTED_IDF_SLAVE_TARGET
```

### 3. 功率旋钮按键步进功能的首次实现

在主程序 `D:\CAT CONTROL\ft710_controller\components\app_controller\app_controller.c` 中完成以下逻辑：

- 删除固定 `1W` 步进宏：

```c
#define POWER_ENCODER_STEP_W 1
```

- 使用全局功率步进变量，初始值为 `2W`：

```c
static uint8_t s_power_step = 2;
static bool s_power_encoder_selecting_step;
```

- 新增步进表：

```c
const uint8_t steps[] = {2, 5, 10};
```

- 功率旋钮普通模式：

```c
delta * (int)s_power_step
```

- 功率旋钮按键 `PB0`：

```c
s_power_encoder_selecting_step = !s_power_encoder_selecting_step;
```

- 进入步进选择模式时：

```text
Power encoder enter step select, step=2W
```

- 旋转功率旋钮时只改变步进，不发送 CAT 功率命令：

```text
Power encoder step select 5W
Power encoder step select 10W
```

- 再按一次退出步进选择模式：

```text
Power encoder exit step select, step=10W
```

- 退出后旋转功率旋钮按刚才选择的步进发送：

```text
Power encoder set 42W step=10W
CAT set PC042; -> ESP_OK
```

### 5. 用户进一步明确 OLED 显示要求

用户明确：

> 步进选择按钮选择步进时候是要在iic接口的0.96寸屏上显示

于是将辅助 OLED 从“只显示功率值”改成“根据当前状态显示功率或步进”。

原逻辑：

- OLED 只缓存 `s_aux_oled_last_power`
- OLED 任务只调用：

```c
aux_oled_show_power(s_state.power_w, false);
```

问题：

- 进入步进选择时，如果 `power_w` 没变，OLED 不刷新
- 即使主程序状态已经进入 step select，小屏仍停留在功率显示

修正后：

- OLED 缓存改为标题和数值：

```c
static char s_aux_oled_last_title[12];
static char s_aux_oled_last_value[12];
```

- 新增统一显示函数：

```c
static void aux_oled_draw_status(const char *title, const char *value)
static void aux_oled_show_status(const char *title, const char *value, bool force)
```

- 功率显示：

```c
aux_oled_show_status("RF POWER", value, force);
```

- 步进显示：

```c
aux_oled_show_status("RF STEP", value, force);
```

- 当前状态显示：

```c
static void aux_oled_show_current(bool force)
{
    if (s_power_encoder_selecting_step) {
        aux_oled_show_power_step(s_power_step, force);
    } else {
        aux_oled_show_power(s_state.power_w, force);
    }
}
```

触发 OLED 强制刷新的位置：

- 进入或退出步进选择时
- 旋转功率旋钮选择 `2W/5W/10W` 时
- 普通功率调节时
- OLED 后台刷新任务中

### 6. 最终操作逻辑

当前最终交互：

1. 开机默认功率调节步进为 `2W`
2. 正常旋转功率旋钮：按当前步进调整 RF Power，并发送 `PCxxx;`
3. 按一次功率旋钮按键 `PB0`：进入功率步进选择模式
4. 此时 0.96 寸 OLED 显示：

```text
RF STEP
2W / 5W / 10W
FT-710
```

5. 在步进选择模式旋转功率旋钮：只在 `2W`、`5W`、`10W` 三档之间选择，不发送 CAT 功率命令
6. 再按一次功率旋钮按键：退出功率步进选择模式
7. 0.96 寸 OLED 回到：

```text
RF POWER
当前功率 W
FT-710
```

8. 之后旋转功率旋钮：按刚才选择的步进调整功率并发送 CAT 命令


该日志属于 ESP-Hosted/WiFi6 从设备连接尝试，不影响本次 CAT-3 CH9102 控制、MCP23017 旋钮和辅助 OLED 功能验证。
