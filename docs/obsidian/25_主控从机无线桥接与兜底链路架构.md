# 主控与从机无线桥接及兜底链路架构

## 1. 当前阶段目标

当前项目先暂时不考虑 ICOM/CI-V，只针对 YAESU 体系展开，首要目标电台为 FT-710。

新的总体方向是：

- ESP32-P4 7 寸触摸屏作为主控端。
- ESP32-S3 3.49 寸触摸屏作为从机/桥接端。
- 从机靠近 FT-710，通过 CAT-3 TTL 串口直接连接电台。
- 主控与从机之间优先无线通信，依次使用 WiFi、BLE。
- 无线失败时，可通过 USB 线连接主控和从机。
- 如果从机完全故障，则允许主控直接使用 USB-CAT-3 连接线或 USB-TTL 模块连接 FT-710 CAT-3 作为最终兜底。

项目的关键设计原则：

```text
UI / 旋钮 / OLED 不直接关心 CAT 物理链路
CAT 命令驱动不关心 WiFi、BLE、USB 传输方式
WiFi 数据库访问不影响电台控制链路
从机第一阶段只做可靠透传和状态显示，不承担复杂电台逻辑
```

## 2. 主控端定位

主控端硬件为微雪 ESP32-P4-WIFI6-Touch-LCD-7B，核心职责是用户交互、CAT 状态模型、电台驱动和链路选择。

主控端承担：

- 1024 x 600 横屏触摸主界面。
- 固定频率输入区域。
- 四个可配置控制面板。
- 五组外接旋钮/OLED 的功能配置。
- YAESU FT-710 CAT 指令生成与响应解析。
- CAT 链路管理：WiFi、BLE、USB-S3、Direct USB-CAT3。
- WiFi 路由器连接、时间同步、本地/UTC 时间切换。
- 未来从数据库/API 同步频道列表、台站列表、预设列表和日志数据。

主控端建议组件框架：

```text
ft710_controller
  main
    app_main.c

  components
    app_controller
      现有主入口，后续逐步瘦身，只负责启动与协调。

    radio_state
      电台状态缓存：VFO-A/B 频率、模式、功率、DNR、WIDTH、链路状态等。

    radio_driver
      YAESU 电台驱动层。第一阶段只实现 FT-710。

    cat_transport
      CAT 传输层。提供 WiFi、BLE、USB-S3、Direct USB-CAT3 四类传输实现。

    cat_link_manager
      链路自动选择、健康检查、故障降级、空闲恢复。

    control_features
      频率、功率、DNR、WIDTH、模式、Band、AF Gain 等功能模块。

    hardware_slots
      五组旋钮和五块 OLED 的硬件槽位管理。

    layout_config
      主屏四个可配置控制块和五组硬件槽位的功能绑定。

    settings_ui
      主控设置菜单，包括电台、链路、WiFi、数据源、硬件槽位配置。

    network_client
      WiFi STA、SNTP、HTTP/REST 数据同步。

    data_store
      NVS/LittleFS 本地缓存与配置保存。
```

## 3. 从机端定位

从机端硬件设想为 ESP32-S3 3.49 寸触摸屏。它不是完整的电台控制器，而是靠近 FT-710 的 CAT 桥接器。

从机端承担：

- CAT-3 TTL UART 与 FT-710 通信，默认 38400 8N1。
- WiFi CAT Bridge：主控通过 TCP 连接从机。
- BLE CAT Bridge：主控通过 BLE UART/GATT 连接从机。
- USB Device Bridge：主控通过 USB 线连接从机，从机以 USB CDC 串口形式暴露。
- 本机 3.49 寸触摸屏显示 WiFi/BLE/USB/CAT 状态。
- 本机 WiFi 基础配置：扫描、SSID、密码、连接、断开、IP 显示。
- 简单诊断：最后 CAT 命令、最后响应、收发计数、错误计数。

从机端建议组件框架：

```text
cat3_bridge_slave
  main
    app_main.c

  components
    cat_uart_driver
      UART 到 FT-710 CAT-3，38400 8N1。

    uplink_wifi_server
      TCP Server，例如监听 7373 端口。

    uplink_ble_uart
      BLE GATT UART 服务，主控作为 BLE Client。

    uplink_usb_cdc
      USB CDC ACM Device，主控作为 USB Host。

    bridge_router
      在 WiFi/BLE/USB uplink 与 CAT UART 之间转发帧。

    slave_ui
      3.49 寸屏状态页和 WiFi 设置页。

    slave_config
      保存 WiFi SSID/密码、BLE 设备名、端口号、串口参数等。

    diagnostics
      统计 last command、last response、rx/tx counters、timeout counters。
```

## 4. 物理链路总览

正常首选链路：

```text
ESP32-P4 主控
  -> WiFi
  -> ESP32-S3 从机
  -> CAT-3 TTL UART
  -> YAESU FT-710
```

无线备用链路：

```text
ESP32-P4 主控
  -> BLE
  -> ESP32-S3 从机
  -> CAT-3 TTL UART
  -> YAESU FT-710
```

有线从机链路：

```text
ESP32-P4 主控 USB Host
  -> USB 线
  -> ESP32-S3 从机 USB CDC Device
  -> CAT-3 TTL UART
  -> YAESU FT-710
```

从机故障最终兜底链路：

```text
ESP32-P4 主控 USB Host
  -> USB-CAT-3 连接线 / USB-TTL 模块
  -> CAT-3 TTL UART
  -> YAESU FT-710
```

## 5. 链路优先级

主控的 CAT Link Mode 建议提供：

```text
Auto
WiFi Bridge
BLE Bridge
USB-S3 Bridge
Direct USB-CAT3
```

Auto 模式自动优先级：

```text
1. WiFi Bridge
2. BLE Bridge
3. USB-S3 Bridge
4. Direct USB-CAT3
```

判断链路是否可用，不能只看网络/设备是否连接，而要做 CAT 级健康检查：

```text
发送 ID;
期待收到 ID0800;
```

只有设备链路建立，并且 FT-710 返回正确 ID，才认为 CAT 链路真正在线。

状态栏建议显示当前实际链路：

```text
CAT WIFI
CAT BLE
CAT USB-S3
CAT USB-DIRECT
CAT OFF
```

设置页显示更详细的链路状态：

```text
Preferred Link: Auto
Active Link: WiFi / BLE / USB-S3 / USB-DIRECT / None
WiFi Bridge: Connected / Timeout / ID Failed
BLE Bridge: Connected / Not Found / ID Failed
USB-S3 Bridge: Ready / No Device / ID Failed
Direct USB-CAT3: Ready / No Device / ID Failed
```

## 6. 主控 CAT Transport 抽象

FT-710 驱动层不直接操作 WiFi、BLE、USB。它只生成 CAT 字符串并解析响应。

传输层统一接口：

```c
typedef enum {
    CAT_TRANSPORT_WIFI_BRIDGE,
    CAT_TRANSPORT_BLE_BRIDGE,
    CAT_TRANSPORT_USB_S3_BRIDGE,
    CAT_TRANSPORT_USB_DIRECT_CAT3,
} cat_transport_type_t;

typedef struct {
    cat_transport_type_t type;

    esp_err_t (*open)(void);
    esp_err_t (*close)(void);
    esp_err_t (*write)(const uint8_t *data, size_t len);
    esp_err_t (*read_frame)(char *out, size_t out_size, uint32_t timeout_ms);
    esp_err_t (*health_check)(void);
} cat_transport_t;
```

上层使用方式：

```text
radio_driver_yaesu_ft710 生成 FA; / PC050; / RL007;
cat_link_manager 选择当前活动 transport
transport 负责真实收发
radio_driver_yaesu_ft710 解析返回并更新 radio_state
```

## 7. 从机 Bridge Router 抽象

从机端不需要知道每个 CAT 命令的业务含义。第一版从机只做分号结尾帧的透明转发。

从机转发规则：

```text
任一 uplink 收到 CAT 命令帧
  -> 写入 CAT-3 UART
  -> 等待 FT-710 返回分号结尾响应
  -> 返回给当前 uplink
  -> 更新状态屏 last command / last response / counters
```

同一时间建议只允许一个 uplink 成为 active uplink，避免 WiFi、BLE、USB 同时写 CAT 串口导致命令交错。

从机 active uplink 选择建议：

```text
1. 已被主控确认并持续发送心跳的链路优先
2. 新链路接入时，如果当前链路空闲超过指定时间，可切换
3. 如果当前链路断开或超时，释放 active uplink
```

从机状态页应显示：

```text
CAT-3: OK / TIMEOUT / OFF
Active Uplink: WiFi / BLE / USB / None
WiFi: SSID / IP / RSSI
BLE: ADV / CONNECTED / OFF
USB: READY / CONNECTED
Last CMD
Last RX
RX Count
TX Count
Timeout Count
```

## 8. WiFi 数据库与 WiFi CAT 的边界

本项目中 WiFi 有两类用途，必须解耦：

| 用途 | 与 CAT 控制关系 | 说明 |
|---|---:|---|
| WiFi CAT Bridge | 是 | 主控通过 WiFi 连接从机，从机透传 CAT-3 |
| WiFi 数据源 | 否 | 主控连接路由器/网络服务，获取频道、台站、预设、日志等 |

重要结论：

```text
WiFi 已连接路由器，不等于 WiFi CAT 可用。
WiFi CAT 不可用，不等于数据库不可用。
数据库不可用，不应影响 CAT 控制。
```

推荐数据源不要让 ESP32-P4 直接连接 MySQL/PostgreSQL 等数据库，而是连接轻量 HTTP/REST API。

未来 API 示例：

```text
GET /api/channels?radio=ft710
GET /api/stations?band=20m
GET /api/presets?radio=ft710
POST /api/logbook
```

主控本地缓存：

```text
/littlefs/channels.json
/littlefs/stations.json
/littlefs/presets.json
```

离线策略：

```text
网络数据源不可用时，使用上次缓存。
缓存也不可用时，只隐藏频道/台站增强功能。
CAT 基本控制始终可用。
```

## 13. USB 方案注意点

ESP32-S3 支持 USB OTG/USB Device，但具体能否直接用从机 USB 口做 USB CDC，要看 3.49 寸触摸屏开发板的 USB 口接法。

需要区分：

```text
USB 口接到 ESP32-S3 原生 USB D+/D-
  可以做 USB CDC Device，适合 USB-S3 Bridge。

USB 口只接到 CH340/CP210x 下载串口芯片
  仍可作为串口桥接，但会和下载日志通道冲突。

板上有两个 USB 口
  一个用于下载日志，一个用于原生 USB CDC，这是最理想状态。
```

因此从机硬件确认时需要记录：

- USB 口数量。
- 每个 USB 口连接到哪里。
- 是否暴露 ESP32-S3 原生 USB D+/D-。
- 是否使用 CH340/CP210x。
- 是否能在运行固件时稳定作为 USB CDC 设备被主控识别。

## 14. 推荐实现顺序

第一阶段：整理主控软件边界。

```text
1. 保持现有 FT-710 功能不变。
2. 抽出 radio_driver_yaesu_ft710。
3. 抽出 cat_transport_usb_direct_cat3。
4. 建立 cat_link_manager，但暂时只启用 Direct USB-CAT3。
```

第二阶段：建立从机最小桥接。

```text
1. 从机 CAT-3 UART 与 FT-710 通信。
2. 从机屏幕显示 CAT 状态。
3. 从机 WiFi STA 配置和 TCP Server。
4. 主控通过 WiFi Bridge 发送 ID;、FA;、PC; 测试。
```

第三阶段：加入 BLE Bridge。

```text
1. 从机 BLE UART 服务。
2. 主控 BLE Client。
3. BLE 链路健康检查。
4. WiFi 失败后自动降级 BLE。
```

第四阶段：加入 USB-S3 Bridge。

```text
1. 从机 USB CDC Device。
2. 主控 USB Host 识别从机 CDC。
3. USB-S3 Bridge 通过 ID; 验证。
4. BLE 失败后自动降级 USB-S3。
```

第五阶段：保留 Direct USB-CAT3 最终兜底。

```text
1. 主控识别 USB-TTL/USB-CAT3 连接线。
2. 从机不可用时直接控制 FT-710。
3. 状态栏明确显示 CAT USB-DIRECT。
```

第六阶段：加入配置系统和数据源。

```text
1. 主控菜单配置链路模式。
2. 主控菜单配置四个控制面板。
3. 主控菜单配置五组旋钮/OLED功能。
4. 主控 WiFi 同步频道、台站、预设数据。
5. 本地缓存并支持离线使用。
```

## 15. 当前结论

主控和从机的总体架构可行，并且适合当前 ESP32-P4 7 寸主控硬件继续运行。

合理边界是：

```text
ESP32-P4 主控：
  负责 UI、状态模型、YAESU CAT 驱动、链路选择、数据库/API同步。

ESP32-S3 从机：
  负责 CAT-3 近端连接、WiFi/BLE/USB 透传、基本状态显示和本地 WiFi配置。

FT-710：
  只通过 CAT-3 接收标准 YAESU CAT ASCII 命令。
```

最终链路策略：

```text
Auto 优先 WiFi
WiFi 不可用用 BLE
BLE 不可用用 USB-S3
从机完全故障才用 Direct USB-CAT3
```

这个设计兼顾了日常无线使用、现场调试、从机维护和最终硬件兜底，不会把任何一个通信方式做成单点故障。
