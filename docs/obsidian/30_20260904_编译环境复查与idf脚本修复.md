# 编译环境复查与 idf 脚本修复

## 用户要求

用户要求检查编译环境，并确认之前的开发编译都是如何完成的。

## 复查结论

当前主项目仍然使用：

- ESP-IDF：`v5.5.5`
- 主工程：`D:\CAT CONTROL\ft710_controller`
- 构建目录：`build_v555`
- 目标芯片：`esp32p4`
- 之前记录的主控烧写串口：`COM4`
- 环境脚本：`D:\CAT CONTROL\idf-v5.5.5.ps1`

## 发现的问题

直接执行旧版：

```powershell
. "D:\CAT CONTROL\idf-v5.5.5.ps1"
```

会调用：

```powershell
C:\esp\v5.5.5\esp-idf\export.ps1
```

但当前本机 ESP-IDF 官方 export 流程会失败，报错：

```text
ERROR: tool xtensa-esp-elf has no installed versions.
ERROR: tool esp32ulp-elf has no installed versions.
idf.py: The term 'idf.py' is not recognized
```

实际磁盘中工具链文件存在：

- `C:\Espressif\tools\riscv32-esp-elf\...`
- `C:\Espressif\tools\xtensa-esp-elf\...`
- `C:\Espressif\tools\esp32ulp-elf\...`
- `C:\Espressif\tools\cmake\...`
- `C:\Espressif\tools\ninja\...`
- `C:\Espressif\tools\python_env\idf5.5_py3.12_env\...`

因此问题不是工具文件物理缺失，而是 ESP-IDF 工具注册/export 状态异常。

## 之前成功编译的方法

Obsidian 历史记录显示，之前遇到同类问题时采用过手动环境变量方式：

```powershell
$env:PYTHONIOENCODING='utf-8'
$env:PYTHONUTF8='1'
$env:ESP_IDF_VERSION='5.5'
$env:IDF_PATH='C:/esp/v5.5.5/esp-idf'
$env:IDF_TOOLS_PATH='C:/Espressif/tools'
$env:IDF_PYTHON_ENV_PATH='C:/Espressif/tools/python_env/idf5.5_py3.12_env'
$env:ESP_ROM_ELF_DIR='C:/Espressif/tools/esp-rom-elfs/20241011'
python C:\esp\v5.5.5\esp-idf\tools\idf.py build
```

该方式曾用于完成主程序、OLED 测试、功率旋钮步进选择等阶段的构建、烧写和实机验证。

## 本轮修复

已修改：

`D:\CAT CONTROL\idf-v5.5.5.ps1`

修复方式：

- 不再调用当前会失败的官方 `export.ps1`。
- 直接设置项目已验证过的 ESP-IDF 相关环境变量。
- 将 Python venv、CMake、Ninja、ccache、RISC-V 工具链、Xtensa 工具链、ULP 工具链、ROM ELF、ESP-IDF tools 加入 PATH。
- 定义 PowerShell 函数 `idf.py`，固定使用：

```powershell
C:\Espressif\tools\python_env\idf5.5_py3.12_env\Scripts\python.exe
C:\esp\v5.5.5\esp-idf\tools\idf.py
```

## 验证结果

```powershell

idf.py --version
cd "D:\CAT CONTROL\ft710_controller"
idf.py -B build_v555 build
```

结果：

构建完成，说明当前最新源码可以编译通过。

## 注意事项

运行 `idf.py` 时仍会显示一条 Python venv 路径提示：

```text
WARNING: Python interpreter ... is not from installed venv ...
```

这是路径格式 `C:\...` 与 `C:/...` 的字符串比较提示，不影响本轮构建。

后续如果希望彻底消除该提示，可以进一步统一 `IDF_PYTHON_ENV_PATH` 的路径格式，但当前不影响编译、链接和固件生成。
